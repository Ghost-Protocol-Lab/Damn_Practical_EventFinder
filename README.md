# Security events hub

A static GitHub Pages site that lists upcoming CTFs, security conferences, meetups and bug bounty programs, online and on-site. A scheduled GitHub Action collects the data every 6 hours and redeploys the site. There is no server, no API key and no third-party request from the page itself.

## Put it online

1. Create a new GitHub repository and push these files to the `main` branch.
2. Open **Settings → Pages** and set **Source** to **GitHub Actions**.
3. Open the **Actions** tab, choose **Update data and deploy**, and click **Run workflow**.

After about a minute the site is live at `https://<your-username>.github.io/<repo-name>/`. It refreshes itself every 6 hours after that.

## Where the data comes from

| Source | What it supplies |
| --- | --- |
| [CTFtime](https://ctftime.org/api/) | CTFs for the next 9 months, online and on-site |
| [tech-conferences/conference-data](https://github.com/tech-conferences/conference-data) | Security conferences with call-for-papers deadlines |
| [arkadiyt/bounty-targets-data](https://github.com/arkadiyt/bounty-targets-data) | Open programs on HackerOne, Bugcrowd, Intigriti and YesWeHack |
| `data/sources.json` | Any calendar feed (`.ics`) you add, such as a Meetup group or a Luma calendar |
| `data/manual.json` | Anything you add by hand |

If one source is down, the events it supplied last time are kept and the page shows a notice saying which source could not be reached.

## Add your own events

Edit `data/manual.json` and commit. The site redeploys on its own.

```json
[
  {
    "title": "null Mumbai monthly meet",
    "type": "meetup",
    "mode": "onsite",
    "start": "2026-11-21T16:00:00+05:30",
    "end": "2026-11-21T19:00:00+05:30",
    "location": "Powai, Mumbai",
    "url": "https://example.com/event",
    "tags": ["null"],
    "description": "Talks and demos."
  },
  {
    "title": "BSides Somewhere",
    "type": "conference",
    "mode": "hybrid",
    "start": "2026-12-05",
    "end": "2026-12-06",
    "location": "Pune, India",
    "url": "https://example.com",
    "cfpUrl": "https://example.com/cfp",
    "cfpEnd": "2026-11-15"
  }
]
```

- `type` is one of `ctf`, `conference`, `meetup`, `bounty`, `other`. Use `bounty` for live-hacking events and bug bounty promotions.
- `mode` is one of `online`, `onsite`, `hybrid`.
- A date such as `2026-12-05` means an all-day event. A date with a time and offset means a timed event, shown in each visitor's own time zone.
- `end`, `tags`, `description`, `cfpUrl` and `cfpEnd` are optional.

## Follow meetup groups and communities

Add the group's calendar link to `data/sources.json`:

```json
{
  "ics_feeds": [
    { "name": "null Mumbai", "url": "https://www.meetup.com/null-mumbai/events/ical/", "type": "meetup" },
    { "name": "OWASP Pune", "url": "https://example.com/calendar.ics", "type": "meetup", "mode": "onsite" }
  ]
}
```

Meetup groups publish a feed at `…/events/ical/`, and Luma calendars have an "Add iCal subscription" link. Check that the link opens in your browser and downloads a `.ics` file before you add it. `mode` is optional: without it, an event is marked online when its location or title mentions Zoom, Discord, "virtual" and similar words.

## What visitors can do

- See what is live or starting soon at the top of the page.
- Filter by type, online or on-site, start date, or call for papers still open, and search by name, city or topic. Filters are saved in the page address, so a filtered view can be shared.
- Add one event to their calendar, or subscribe to the whole list. The subscribe feed is `data/events.ics`.
- Browse bug bounty programs by platform, payout and name.

## Files

```
index.html                       the page
assets/style.css, app.js         look and behaviour
assets/core.js                   dates, filters and calendar export (no DOM, so it is testable)
assets/fonts/                    Barlow, self-hosted (SIL Open Font License)
scripts/fetch_events.py          collects everything into data/ (Python standard library only)
data/events.json, programs.json  generated by the workflow, read by the page
data/events.ics                  calendar feed, generated
data/manual.json, sources.json   yours to edit
.github/workflows/               the schedule, tests and deploy
```

## Run and test locally

```
python3 scripts/fetch_events.py      # refresh data/ (needs internet)
python3 -m http.server               # then open http://localhost:8000
python3 -m unittest discover -s scripts
node --test tests/core.test.js
```

Open the page through `http.server`, not by double-clicking `index.html`, because browsers block a page from reading local data files.

## Limits

- CTFtime asks for a descriptive `User-Agent`, which the script sends. If CTFtime ever starts refusing requests from GitHub's servers, the CTF list keeps its last data and the page shows the notice. Adding CTFs to `manual.json` works as a stopgap.
- No free feed of bug bounty live-hacking events exists, so those come from `manual.json`. The programs tab covers the standing programs.
- Conference dates are calendar days as published by the organisers, with no time zone.
- Data can be up to 6 hours old, and calendar apps check subscribed feeds on their own schedule, often daily.
